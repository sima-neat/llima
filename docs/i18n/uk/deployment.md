# Розгортання моделі

## Огляд

Після компіляції моделі необхідно розгорнути на пристрої Modalix для виконання. Model Compiler надає утиліту `llima-deploy`, щоб спростити цей процес:

``` console
sima-user@docker-image-id:/home/docker$ llima-deploy <source_directory> <destination_directory>
```

Де:

- `source_directory` – шлях до каталогу зі скомпільованою моделлю (містить `sima_files/` з підкаталогами `devkit/`, `mpk/` і, за потреби, `npy_files/`).
- `destination_directory` – цільовий каталог на пристрої Modalix у форматі `[user@]host:/path` або локальний шлях.

Під час виконання цієї команди інструмент розгортання виконує такі етапи:

1.  **Перевіряє**, чи містить вихідний каталог необхідні файли (`sima_files/devkit/` та `sima_files/mpk/`).
2.  **Перевіряє** віддалене місце призначення перед будь-якою локальною роботою (див. розділ «Перевірка віддаленого місця призначення» нижче).
3.  **Витягує** ELF-файли з MPK-архівів (`*.tar.gz`).
4.  **Синхронізує** наступне з кінцевою точкою за допомогою `rsync`:
    - `devkit/` – файли для оркестрування середовища виконання.
    - `elf_files/` – Вилучені бінарні файли.
    - `npy_files/` – ваги адаптера LoRA (автоматично додаються, якщо вони є).

Цей інструмент використовує `rsync` для ефективного передавання файлів, і він пропускатиме файли, які вже є в актуальній версії.

## Процес розгортання

Після компіляції вашої моделі за допомогою `llima-compile`, ви отримаєте таку структуру каталогів:

``` text
Llama-3.2-3B-Instruct_out/
├── onnx_files/
└── sima_files/
    ├── devkit/
    └── mpk/
```

Щоб здійснити розгортання на пристрої Modalix, у вас є два варіанти:

**Варіант А: Пряме розгортання на пристрій Modalix**

Якщо ваша основна машина має мережевий доступ до пристрою Modalix:

``` console
sima-user@docker-image-id:/home/docker$ llima-deploy Llama-3.2-3B-Instruct_out sima@192.168.1.20:/media/nvme/llima/llama3_2
```

**Варіант B: Розміщення в локальній папці для подальшого ручного перенесення**

``` console
sima-user@docker-image-id:/home/docker$ llima-deploy Llama-3.2-3B-Instruct_out llama3_2
sima-user@docker-image-id:/home/docker$ scp -r llama3_2 sima@192.168.1.20:/media/nvme/llima/
```

:::note
`192.168.1.20` — це приклад IP-адреси Modalix. Використовуйте IP-адресу вашого пристрою.
:::

Після розгортання підключіться до пристрою Modalix за допомогою SSH і запустіть модель:

``` console
modalix:~$ ssh sima@192.168.1.20
```

Потім запустіть модель за допомогою командного рядка `llima`. Детальнішу інформацію див. у документації [LLiMa CLI](runtime.md).

``` console
modalix:~$ llima run <model_name>
```

## Перевірка віддаленого місця призначення

Для віддаленого місця призначення `llima-deploy` підключається до пристрою ще до вилучення ELF-файлів. Він створює цільовий каталог, перевіряє, чи доступний він для запису, і повідомляє обсяг вільного місця:

``` console
sima-user@docker-image-id:/home/docker$ llima-deploy Llama-3.2-3B-Instruct_out sima@192.168.1.20:/media/nvme/llima/llama3_2
Checking sima@192.168.1.20:/media/nvme/llima/llama3_2 ...
sima@192.168.1.20's password:
Destination sima@192.168.1.20:/media/nvme/llima/llama3_2 OK (402.3 GB free).
```

Запит пароля або ключа хоста з’являється саме на цьому етапі, а `rsync` повторно використовує те саме SSH-з’єднання, тож решта розгортання виконується без участі користувача. Якщо пристрій недоступний або цільовий каталог недоступний для запису, команда зупиняється, нічого не вилучивши. Якщо вільного місця, імовірно, менше, ніж потрібно для моделі, виводиться попередження, і розгортання продовжується.

Щоб повністю уникнути запитів пароля, один раз установіть SSH-ключ на пристрій:

``` console
sima-user@docker-image-id:/home/docker$ ssh-copy-id sima@192.168.1.20
```

Параметри:

- `--rsh "<command>"` - команда віддаленої оболонки для перевірки та для `rsync`, наприклад `--rsh "ssh -p 2222 -i ~/.ssh/modalix"`. За замовчуванням використовується змінна середовища `RSYNC_RSH`. Користувацька віддалена оболонка використовується без змін і без спільного з’єднання.
- `--no-preflight` - пропустити перевірку й підключатися до пристрою лише під час `rsync`.

`llima-deploy-lora` виконує ту саму перевірку, а також перевіряє, що цільовий каталог моделі вже містить `elf_files/`.

## Спекулятивні моделі декодування.

Коли `llima-compile` отримує `--draft_model_path`, її вивід містить цільові та чернеткові результати компіляції в одному батьківському каталозі. Розгорніть цей батьківський каталог за допомогою однієї команди:

``` console
llima-deploy compiled-eagle3 spec-decoding-output
```

Розгорнутий пакет містить дві звичайні директорії моделей для середовища виконання:

``` text
spec-decoding-output/
├── <target-model>/
│   ├── devkit/
│   └── elf_files/
└── <draft-model>/
    ├── devkit/
    └── elf_files/
```

Запустіть батьківську директорію, щоб LLiMa могла ідентифікувати та завантажити обидві моделі з їхнього збереженого файлу конфігурації для спекулятивного декодування:

``` console
llima run spec-decoding-output
```

## Усунення несправностей.

**Помилка: «Cannot reach ...»**

Перевірте IP-адресу пристрою, мережеве з’єднання та облікові дані SSH.

**Помилка: «Destination ... is not writable»**

Переконайтеся, що накопичувач змонтовано (наприклад, `/media/nvme`) і що користувач SSH має право запису в цільовий каталог.

**Помилка: «devkit directory cannot be found»**

Переконайтеся, що вихідний каталог є каталогом, який створила команда `llima-compile`, і що в ньому міститься підкаталог `sima_files`.

**Помилка: «mpk directory cannot be found»**

Перевірте, чи успішно завершено компіляцію. У каталозі `sima_files/mpk/` мають міститися файли `.tar.gz`.

**Повільне розгортання**

- Використовуйте `rsync` зі стисненням: за замовчуванням інструмент використовує `rsync -aP`.
- Розгорніть систему на NVMe-накопичувачі в Modalix, щоб пришвидшити завантаження моделі.
- Розгляньте можливість розгортання лише змінених файлів під час компіляції за допомогою `--resume`.
